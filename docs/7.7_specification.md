# Task 7.7 Specification — Comments with Entra ID

## Purpose

The finished feature must be independently verifiable, testable, and protected against comment-author spoofing through the deployed Rayfin row-level security policy.

Detailed test cases live in [`docs/7.7_test_plan.md`](7.7_test_plan.md) to keep this specification small and context-efficient.

## Functional requirements

### Comment storage

Comments must be stored in Rayfin DAB/MSSQL through `client.data.Comment`. They must not be written to the Lakehouse or semantic model.

Logical fields:

| Field | Required | Requirement |
| --- | --- | --- |
| `comment_id` | yes | Stable UUID comment identifier. |
| `project_id` | yes | Lakehouse project identifier, max 64 chars. |
| `task_id` | no | Lakehouse task identifier, max 64 chars; absent/null means project-level. |
| `user_upn` | yes | Caller email/UPN, max 256 chars; must match `claims.email` for writes. |
| `comment_text` | yes | Trimmed non-empty text, max 2000 chars. |
| `created_datetime` | yes | UTC creation timestamp. |

### Identity enforcement

The deployed Rayfin backend is the source of truth:

- authenticated read is allowed,
- create/update/delete are allowed only when `claims.email == item.user_upn`,
- spoofed writes with a different `user_upn` must fail even if the browser payload is tampered with.

### Project-level comments

The single-project detail page must show a project-level comments panel with loading, error, empty, newest-first list, author UPN, timestamp, and add-comment form.

### Task-level comments

The tasks grid must show a comment-count column. Clicking a task comment count opens a drawer scoped to that task. Posting in the drawer creates a comment with that task's `task_id`.

### Add-comment form

The form must:

- block empty/whitespace-only posts,
- allow exactly 2000 characters,
- reject more than 2000 characters,
- show a character counter,
- disable Post while submitting,
- render successful posts optimistically,
- roll back failed optimistic posts and show an error.

### Security

- Render comment text as text, not raw HTML.
- Do not log full comment bodies at info level.
- Keep Teams/webhook/function work deferred.
- Do not commit secrets or deployment-local files.

## Acceptance criteria

Task 7.7 is complete only when:

- `npm test` passes from `apps/Jobsite_Twin`.
- `npm run build` passes from `apps/Jobsite_Twin`.
- Project-level comments can be read and posted.
- Task-level comments can be read and posted.
- Task comment counts are visible and scoped by `task_id`.
- Empty and over-limit posts are blocked.
- Comment text is safe-rendered as text.
- Honest Rayfin insert succeeds and spoofed insert fails against the deployed backend.
- `Comment` primary-key behavior is fixed or explicitly documented.
- No Teams webhook/function work is introduced.
- No secrets or deployment-local files are committed.
