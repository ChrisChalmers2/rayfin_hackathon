# Lakehouse Setup — The Data Foundation

The Fabric Lakehouse holds all the reference and analytical data for the Construction Intelligence Demo. It's populated by a single deterministic notebook so anyone can regenerate the exact same dataset.

## Recommended Lakehouse name
`The_Jobsite_LH`

## What's in it
Four Delta tables, generated by `notebooks/01_synthetic_data_construction.ipynb`:

| Table | Rows | What it holds |
|---|---|---|
| **projects** | 20 | One row per construction project. Columns include `project_id`, `project_name`, `project_type`, `status`, `risk_score`, `is_outlier`, `location`, `start_date`, `planned_end_date`, `actual_end_date`. |
| **tasks** | 347 | Individual construction tasks within projects (Excavation, Foundation, Roofing, etc.). Columns include `task_id`, `project_id`, `location_id`, `task_name`, `task_status`, `planned_start_date`, `planned_end_date`, `actual_end_date`, `dependency_task_id`. |
| **costs** | 1,041 | Cost entries associated with tasks. Columns include `cost_id`, `project_id`, `task_id`, `cost_category`, `planned_cost`, `actual_cost`. |
| **locations** | 116 | Physical zones within each project (Basement, Floor 1, Roof, etc.) with 3D coordinates. Columns include `location_id`, `project_id`, `zone_name`, `x_coord`, `y_coord`, `z_coord`. |

*(Exact column set may vary slightly — inspect the notebook's Section 9 validation cells for the authoritative schema.)*

## How to populate it (first time)

1. In your Fabric workspace, create a new Lakehouse. Name it `The_Jobsite_LH` (or update the notebook if you use a different name)
2. Import the notebook: **New Item → Import Notebook → select** `notebooks/01_synthetic_data_construction.ipynb`
3. Attach the Lakehouse to the notebook
4. Run All
5. First run takes ~5-10 minutes on a Trial or F-SKU capacity

## How to re-run
Just Run All again. The notebook uses `saveAsTable(mode="overwrite")`, which safely replaces existing tables. Deterministic — same input every time thanks to `SEED = 42`.

## Validation
The notebook's Section 9 asserts row counts, distribution rules, and task-zone affinity. If those cells pass, your data is good.

## Data model at a glance

    projects (20)
      ├── locations (116, joined on project_id)
      └── tasks (347, joined on project_id)
            └── costs (1,041, joined on task_id)

Tasks connect to locations via `location_id`.
